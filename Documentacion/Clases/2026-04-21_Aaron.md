### Roles identificados

- **Visitante**: usuario principal de la app. Consulta información del parque, compra entradas
  y se inscribe a actividades. Puede ser técnico o no técnico; accede desde su celular.
- **Administrador del parque**: gestiona los datos del sistema (horarios, actividades, exhibiciones)
  por fuera de la app, a través del equipo interno. No es un rol de la app móvil.

---

### MVP – Justificación del alcance

El MVP apunta a validar la recepción de la aplicación con las funcionalidades de mayor valor
para el visitante y mayor interés estratégico para el parque (especialmente el pago electrónico).

#### US incluidas en el MVP

| #   | User Story                         | Justificación de inclusión                                                                                                                                 |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Comprar entradas                   | Señalada explícitamente por el cliente como fundamental para probar la app; incluye pago electrónico (MercadoPago), que se espera sea el método más usado. |
| 2   | Visualizar mapa interactivo        | Herramienta central de orientación; mejora directa de la experiencia del visitante dentro del parque.                                                      |
| 3   | Consultar horarios de alimentación | Información dinámica y de alta demanda; diferencia la app de una guía estática.                                                                            |
| 4   | Consultar exhibiciones             | Enriquece la visita con info de cada especie; valor educativo y de entretenimiento.                                                                        |
| 5   | Consultar actividades diarias      | Permite al visitante planificar su jornada antes y durante la visita.                                                                                      |
| 6   | Inscribirse a actividades diarias  | Gestiona cupos limitados y permite planificación anticipada del parque.                                                                                    |

#### US excluidas del MVP

| US excluida                                 | Motivo de exclusión                                                                                                                    |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Registrar usuario / iniciar / cerrar sesión | Solo necesaria para comprar entradas; puede resolverse de forma simplificada sin US separada. Se difiere o absorbe en la US de compra. |
| Notificaciones de horarios de alimentación  | El cliente la señaló explícitamente como funcionalidad de versión posterior.                                                           |
| Ubicación en tiempo real en el mapa         | Idem anterior: mencionada explícitamente como mejora futura por el cliente.                                                            |

### User Story: Visualizar mapa interactivo

```
Como Visitante
Quiero poder visualizar un mapa interactivo del parque
Para orientarme y encontrar fácilmente los puntos de interés durante mi visita
```

**Estimación:**

| Método    | Valor | Razonamiento                                                                                                         |
| --------- | ----- | -------------------------------------------------------------------------------------------------------------------- |
| Fibonacci | 5     | Requiere renderizado de mapa con sectores diferenciados, múltiples íconos y lógica de click; complejidad media-alta. |
| Talla     | L     | Varias piezas visuales e interactivas; bien acotada pero no trivial.                                                 |

> Escala de referencia: Fibonacci (1-2-3-5-8-13) y Tallas (S/M/L/XL) se usan de forma relativa.  
> El valor absoluto no importa; lo que importa es la comparación entre historias.  
> Ej: una US de 8 puntos representa aproximadamente el doble de esfuerzo que una de 5.

```
--- Criterios de aceptación ---
Debe visualizar una vista panorámica de todo el parque.
Debe mostrar los diferentes sectores diferenciados por colores (terrestre, acuático, aéreo).
Debe visualizar íconos informativos:
  - Ícono "Inodoro" para baños distribuidos en el parque.
  - Ícono "Bolsa" para puntos de venta.
  - Ícono "Micrófono" para el show especial del día.
Debe mostrar el nombre y horario del show al hacer click en el ícono de Micrófono (solo si hay un show programado para ese día).
Puede no mostrar el ícono de Micrófono si no hay show programado.
```

> Criterio excluido del MVP:
> "Puede visualizar la ubicación del visitante en tiempo real" → se difiere a versión posterior
> (mencionado por el cliente como mejora futura).

```
--- Pruebas de usuario ---
Probar que se visualiza el mapa con la vista panorámica del parque (PASA).
Probar que cada sector se distingue visualmente por color (PASA).
Probar que los íconos de Inodoro, Bolsa y Micrófono aparecen en el mapa (PASA).
Probar clickear el ícono de Micrófono con show programado: muestra nombre y horario (PASA).
Probar clickear el ícono de Micrófono sin show programado: no muestra info o no aparece el ícono (PASA).
Probar que el ícono de Micrófono no muestra información incorrecta al hacer click (PASA).
```

### User Story: Comprar entradas

```
Como Visitante registrado
Quiero poder comprar entradas para el parque a través de la app
Para agilizar mi ingreso y pagar de forma electrónica sin pasar por boletería
```

**Estimación:**

| Método    | Valor | Razonamiento                                                                                                                                                 |
| --------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Fibonacci | 8     | Involucra registro/login, selección de entradas, cálculo de precios por edad, integración con MercadoPago y envío de mail de confirmación; alta complejidad. |
| Talla     | XL    | Múltiples pasos, validaciones, integración externa y flujo de confirmación.                                                                                  |

```
--- Criterios de aceptación ---
Debe requerir que el visitante esté registrado (mail + contraseña) para poder comprar.
Debe permitir seleccionar la fecha de visita deseada.
Debe permitir indicar la cantidad de entradas (mínimo 1, máximo 10).
Debe solicitar la edad de cada visitante para calcular el precio correspondiente.
Debe mostrar el monto total antes de confirmar el pago.
Debe ofrecer dos formas de pago:
  - Efectivo: indica que el pago se realiza en boletería al ingresar.
  - Tarjeta: redirige al visitante a MercadoPago para completar el pago de forma segura.
Debe enviar un mail de confirmación con las entradas al finalizar la compra. Las entradas deben ser verificables al momento de ingresar al parque.
```

```
--- Pruebas de usuario ---
Probar acceder a "Comprar entradas" sin estar registrado: solicita registro o login (PASA).
Probar seleccionar una fecha de visita válida (PASA).
Probar ingresar 0 entradas: no permite continuar (FALLA).
Probar ingresar 11 entradas: no permite continuar (FALLA).
Probar ingresar 10 entradas con las edades correspondientes: muestra el monto total (PASA).
Probar seleccionar pago en efectivo: confirma la compra sin redirigir (PASA).
Probar seleccionar pago con tarjeta: redirige correctamente a MercadoPago (PASA).
Probar completar el pago con tarjeta: se recibe mail de confirmación (PASA).
Probar que las entradas generadas son verificables al ingresar al parque (PASA).
```
